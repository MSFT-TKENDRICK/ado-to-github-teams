# Area — documentation

## Scope

Every contributor-facing prose surface: `README.md`, `CONTRIBUTING.md`, `AGENTS.md`,
`SECURITY.md`, everything under `docs/`, and every `SKILL.md` under `skills/`. Also the
`.github/skills/*/SKILL.md` mirror generated by `pnpm squad:build` — those must never be
hand-edited but must not drift from `squad.config.ts` either.

## Nine-category pains this area may reveal (per [../workflow.md](../workflow.md))

- **3. Discoverability failures.** Can a fresh clone locate the shortest path to a running
  local change without reading every doc? README currently has a `## Contributor quick start`
  section — verify it still resolves to real commands and not deleted script names.
- **9. Documentation-vs-reality mismatch.** The strongest and most frequent DX regression in
  this repo. Examples known to have occurred: `personas.ts` cited an outdated root script
  count; README named scripts that had been renamed.
- **1. Developer pains and frustration points.** Excess prose, contradictory advice across
  files, or "see also" chains that never bottom out.
- **5. Poor or missing feedback and error messages.** Docs that describe error paths the code
  does not actually take.

## Repo-specific anchors to check

- README.md `## Contributor quick start` — must name only real `package.json` scripts.
  Asserted by `test/unit/documentation/dx-docs.test.ts` (`names only real package.json scripts
in the README quick-start section`).
- CONTRIBUTING.md `## Common commands` table — same contract, same drift gate.
- CONTRIBUTING.md quotes a literal root pnpm script count in prose; `src/experience/personas.ts`
  also cites `${scriptCount} root pnpm scripts` for Theo's `commandDiscoverability` rationale.
  Both must equal `Object.keys(package.json.scripts).length`.
- `docs/testing.md` "Two evidence loops, isolated by domain" section describes the DX loop and
  cites `pnpm optimize:dx`.
- `AGENTS.md` is the authoritative policy document; any DX prose that contradicts it is a
  documentation-vs-reality failure by definition.
- Retired names never resurface: `optimize-devx`, `optimize:devx`, `devx-docs`. Guarded across
  README.md, CONTRIBUTING.md, docs/testing.md, AGENTS.md, squad.config.ts, and package.json.

## Supporting numeric signals from `src/experience/dev-experience.ts`

- `documentedScriptRatio` — an approximate coverage number for whether every `package.json`
  script is named in prose. Supporting evidence only; the drift gate is authoritative.

## Likely evidence shape for a change in this area

Per [../qualitative-evidence.md](../qualitative-evidence.md):

1. A concise, human-readable description of the prose change (what was renamed, deleted,
   corrected, or clarified) and which pain category it removes.
2. The updated `README.md`/`CONTRIBUTING.md`/`docs/*`/`AGENTS.md`/`SKILL.md` file(s) in the
   **same coherent commit**.
3. If a `package.json` script or generated Squad asset was renamed, the drift-gate assertions
   in `test/unit/documentation/dx-docs.test.ts` must be re-run and remain green.

Do **not** invent before/after readability scores or word-count metrics; there are none in this
loop.
