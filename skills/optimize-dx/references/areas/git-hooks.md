# Area — git hooks

## Scope

`lefthook.yml` at the repo root, the `lefthook` devDependency that installs the binary,
`.git/hooks/pre-commit` and `.git/hooks/pre-push` generated by `pnpm install`, and the
non-negotiable "never bypass" rule that keeps hook-enforcement claims honest.

## Nine-category pains this area may reveal

- **8. Setup/build/test/hook/lint/agent-config friction.** A hook that runs the whole
  `pnpm check` (contract + integration + package smoke) on every push is 90-second-plus
  friction per push. The current design intentionally runs only the `dx-gate` subset on
  pre-push to keep push under three minutes; the full gate is CI-enforced.
- **5. Poor or missing feedback and error messages.** A silently skipped hook (fail-open)
  is worse than no hook, because the contributor believes safety was applied.
- **9. Documentation-vs-reality mismatch.** `CONTRIBUTING.md`'s `## Git hooks` section
  quotes the exact commands and the wall-clock reasoning; if `lefthook.yml` drifts, that
  prose must move with it.

## Repo-specific anchors to check

- `lefthook.yml` currently defines:
  - **pre-commit** (parallel):
    - `format-check`: `pnpm exec prettier --check {staged_files}` for `.ts/.mts/.cts/.tsx/.js/.mjs/.cjs/.json/.md/.yml/.yaml`
    - `lint-staged`: `pnpm exec eslint {staged_files}` for `.ts/.mts/.cts`
    - `secrets`: `pnpm secrets:scan`
  - **pre-push**:
    - `dx-gate`: `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test:unit`
- The comment at the top of `lefthook.yml` names the wall-clock number (91.1s on the
  reference workstation) and links to `CONTRIBUTING.md` for the sizing justification. That
  number is a documented artifact, not a moving supporting signal.
- `lefthook` is a **pinned** devDependency (`2.1.10`); `pnpm install` runs
  `lefthook install`, which regenerates `.git/hooks/*` in the current worktree.
- The "never bypass" rule (`--no-verify`, `LEFTHOOK=0`, `SKIP=...`) is called out in
  `CONTRIBUTING.md`, `skills/optimize-dx/SKILL.md`, and
  [../safety-and-delivery.md](../safety-and-delivery.md). All three are load-bearing.

## Supporting numeric signals from `src/experience/dev-experience.ts`

- `hookEnforcementStatus` — must be `enforced`, meaning **both** `lefthook.yml` and the
  `lefthook` devDependency are present. Either alone yields `fail-open`.

## Likely evidence shape for a change in this area

1. Description of the hook change (a command added, removed, moved from pre-commit to
   pre-push, or vice versa), the wall-clock impact, and which category it addresses.
2. Updated `lefthook.yml` **and** updated `CONTRIBUTING.md` `## Git hooks` section (which
   quotes the current commands) in the same commit.
3. Green `test/unit/documentation/dx-docs.test.ts` proving both `lefthook.yml` still
   contains `pre-commit:`, `pre-push:`, and `secrets:scan` and the `lefthook`
   devDependency still exists.
4. **Never** commit a change that widens the pre-push cost beyond ~3 minutes measured
   locally; that would silently push contributors toward `--no-verify` and invalidate every
   hook-enforcement claim this skill makes.
